# Feature Phasing Decision

## Status

Accepted

## Context

MONARQ contains multiple layers: access, daily routines, learning, community, progression, events, and commerce. A phased build is needed so the team can ship progressively without losing system coherence.

## Decision

Build features in phases:

## Phase 1

- auth and access
    
- app shell
    
- member profile
    
- home / daily OS
    
- basic teachings
    
- basic challenge/progression foundation
    

## Phase 2

- community feed
    
- comments / interactions
    
- richer progression and leaderboard
    
- events and calls
    

## Phase 3

- drops and commerce integration
    
- notification improvements
    
- advanced member identity
    
- admin tools
    

## Phase 4

- AI coach
    
- deeper automation
    
- more advanced community and growth systems
    

## Why this was chosen

This sequencing follows dependency logic and supports a progressive launch approach. It reduces rework and keeps the build aligned with capacity.creworklabs+1

## Consequences

## Pros

- Better execution focus
    
- Lower complexity at each step
    
- Cleaner testing and iteration
    
- Easier use of Claude in focused phaseskwiqwork+1
    

## Cons

- Some exciting features arrive later
    
- Requires patience and roadmap discipline
    

## Revisit later if

- business priorities change
    
- user testing changes what should move earlier

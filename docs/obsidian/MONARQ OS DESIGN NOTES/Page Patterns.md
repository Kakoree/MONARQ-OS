# Page Patterns

## Purpose

This note defines the expected structure of MONARQ’s major page types.

## Pattern approach

Pages should feel like different rooms inside the same system. They can have different purposes, but they must still share the same brand language, shell, spacing rules, and component logic.1.
## Main page types

## Home

Should feel like a command center: hero area, quick actions, daily plan/check-in, challenge progress, community highlights, and live momentum.101.

## Teachings

Should feel like structured knowledge and growth: featured content, clear lesson cards, progression, and locked/unlocked learning.

## Community

Should feel like an elevated social feed: wins, reflections, progress, images, comments, and tags, without becoming noisy.91

## Challenges

Should feel like commitment and measurable progress: active challenge cards, XP, participation, and progress submission.

## Events

Should feel like live access and belonging: upcoming events, calls, attendance, and easy join actions

## Members

Should feel like a private member directory: identity, rank, short bio, and profile access.

## Leaderboard

Should feel aspirational and elegant: rank, XP, progress, and prestige without game-like chaos.

## Discipline Schedule

Should feel ritualized and trackable: habits, streaks, completions, and daily consistency.

## What to avoid

- Each page becoming a separate design language.
    
- Overly dense dashboard patterns everywhere.
    
- Feature pages that feel more important than the system itself.
    
- Repetition with no hierarchy.
    

## Build rule

Claude Code should use these page patterns as structure guides. If a page needs more depth later, it can get its own dedicated note.
